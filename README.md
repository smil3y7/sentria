# Sentria — Hub

Central hub for the Sentria ecosystem: a modular set of tools for dream
exploration, lucid dreaming, symbolic continuity, and reflective
consciousness research.

**Live:** https://sentria-hub.vercel.app/ *(update once a custom domain is
live — see the SITE_URL constant in sentria-build/build.py)*

---

## What's in this repo

This repository **is** the deployed site — everything in it is served
directly by Vercel as static files. There's no build step on Vercel's side;
what you upload here is exactly what visitors see.

```
/
├── index.html          ← homepage (constellation UI, app cards, signup)
├── about.html           ← About page (English)
├── privacy.html         ← Privacy policy (English)
├── lab.html              ← Lab page (English)
├── contact.html         ← Contact page (English)
├── sl/
│   ├── about.html        ← About page (Slovenian)
│   ├── privacy.html      ← Privacy policy (Slovenian)
│   ├── lab.html          ← Lab page (Slovenian)
│   └── contact.html      ← Contact page (Slovenian)
├── logo.png
├── logo-mark.png
├── favicon.png
├── screenshots/
├── robots.txt
├── sitemap.xml
└── README.md            ← this file
```

## Tech stack

- Plain HTML, CSS, and JavaScript — no framework, no build tools required
  to run the site itself
- Hosted on **Vercel** (Hobby plan), auto-deploys whenever files change
  in this repo
- Fonts loaded from Google Fonts (Cormorant Garamond, DM Sans, DM Mono)
- Forms (newsletter signup, contact) handled by **Formspree**
- No backend, no database, no build pipeline on the Vercel side

## Nothing here is hand-edited

Every file in this repo — including this README, `sitemap.xml`, and every
page — is generated by a small local build tool (the `sentria-build`
project, kept separately on your machine, not in this repo). It lives in
a sibling folder and is run with `python build.py`, which writes straight
into this folder.

Source of truth for each part of the site:
- **Card content** (name, description, links, screenshots, status badges)
  for every app on the homepage and Lab page — `apps.json`
- **All text**, in both languages — `lang/en.json` + `lang/sl.json`
- **Page copy** for About/Privacy/Lab/Contact — `content/en/*.html` +
  `content/sl/*.html`
- **Layout/styling** — `templates/`

Don't edit files in this repo directly — edit the source in `sentria-build`
and rebuild, or the next build will silently overwrite your change.

## Deploying

Changes are uploaded via **GitHub's web UI** (individual file uploads),
not the local git CLI. After running `python build.py`:

1. Open the synced output folder
2. Upload the changed files to this repo via GitHub's web UI

**Important for multi-file changes:** if a change touches more than one
file — for example a shared CSS rule used by several pages — upload all
the changed files together in the same commit/upload. Uploading them
separately can leave the live site in a half-updated state for the few
minutes between uploads.

## Everything except the homepage is bilingual via real URLs

The homepage uses a JavaScript-based language toggle (one URL, `/`, text
swaps client-side). About, Privacy, Lab, and Contact all exist as separate,
independently indexable real pages per language — e.g. `/lab.html` (English)
and `/sl/lab.html` (Slovenian) — so each language is properly crawlable by
Google. `sitemap.xml` lists all of them and is generated automatically, so
it can't silently fall out of sync the way a hand-maintained one can.

## Adding a new module to the hub

1. Add an entry to `apps.json` in the `sentria-build` project (id, tier —
   `core` or `lab` —, status, links, screenshot filename)
2. Add matching translation strings for it to `lang/en.json` and
   `lang/sl.json`
3. Add its screenshot to `sentria-build/static/screenshots/`
4. Run `python build.py` — the build aborts with a clear error if any
   required translation key is missing, so you can't ship a broken card
5. Review the synced output, then upload the changed files here

## Known limitations (by design, for now)

- The homepage uses JS-only language switching, so only one language is
  indexable by search engines for it specifically. About/Privacy/Lab/
  Contact don't have this problem (see above).
- Several ecosystem modules (Somnia, Orbis, Limina, etc.) are separate
  projects with their own repos and Vercel deployments — this hub only
  links out to them, it doesn't contain their code.
